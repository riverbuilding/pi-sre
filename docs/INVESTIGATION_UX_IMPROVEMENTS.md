## 最新目标与迁移影响

撤回下文 /incident new --force、next selection、调查归属和原子替换的优化提案，不实施中间方案。用户通过 steering 调整本轮、通过逐条 follow-up 继续或换题；显式取消停止所属调用，迟到结果不串入新请求。界面展示当前选择/可用性、实际执行 profile 和 MCP 状态，无 Incident ID 或 next-selection 状态。

## 既有设计与实现记录（保留历史，不作为新方案实施要求）

记录日期：2026-10-29。状态：后续优化提案，尚未实现，不改变当前 Phase 4 行为或验收结论。

## 当前行为与问题

- 没有未结束的 Incident 时，符合条件的普通用户输入会在模型执行前自动创建 Incident；需要模型凭证预检通过，并具有可用的诊断范围。
- 已有 `new` / `investigating` 状态的 Incident 时，后续普通输入继续该调查，不自动创建新 Incident，也不改变其范围。
- 问题文本中的集群名称不决定调查权限。Incident 捕获创建时的 cluster selection；调查期间 `/clusters` 修改的是 next selection。
- `/incident new <问题>` 显式创建或替换调查，但目前不会自动将问题提交给模型执行。
- 模型执行期间，`/incident new <问题>` 提示 `Wait for active work before starting an incident.`，既不中断，也不排队创建。用户需要先取消执行，再创建调查，再发送问题。
- 仅取消模型执行不会结束 Incident。继续同一调查时，UI 保留相同的 Investigation ID 和 scope，但没有固定的“本次输入继续已有调查”提示；用户可通过 `/incident` 检查归属。

这些行为使“停止当前调查并立即开始另一个调查”需要多次操作，也容易让用户误认为新问题或 next selection 已经切换了当前调查。

## 建议：显式中断并开始新调查

建议提供以下命令，具体语法和实现仍待设计确认：

```text
/incident new --force <问题>
```

`--force` 的含义仅是允许中断执行并替换调查，不扩大 cluster scope，不绕过 MCP、凭证或只读策略。

期望流程：

1. 校验命令、问题和 next selection，尽量在中断前发现无法创建新调查的原因。
2. 取消当前模型执行，以及关联的正在执行和排队中的诊断调用；等待取消和清理完成。
3. 在提交替换前重新验证绑定、范围和连接状态。取消等待期间发生的状态变化不能被忽略。
4. 新调查能够成功创建时，将未结束的旧 Incident 标记为 `inconclusive`，记录用户主动替换的原因，并创建使用 next selection 的新 Incident。
5. 将新问题提交给模型，立即执行调查。新 Incident 使用独立的证据、假设和诊断预算。

取消期间已经完成并合法提交的证据仍属于旧 Incident。迟到的旧调用结果不得写入新 Incident，取消的工作不得生成虚假的成功证据。Incident 替换不等于创建或替换 Pi AgentSession，也不隐含清空会话历史。

如果新建校验失败，不应提前将旧 Incident 标记为结束。如果已中断执行后才发生失败，应保留旧调查及其证据、预算和范围，并明确告知用户：执行已停止，新调查未创建。取消无法确认完成时，不得宣称新调查已经开始。

## 建议：明确调查归属与切换反馈

- 普通输入继续未结束的调查时，在 UI 给出简短、固定的归属反馈：继续的 Incident ID 和有效 scope。
- next selection 与当前 scope 不同时，明确展示两者；输入中提及范围外集群不自动修改权限。
- 强制切换期间展示“正在停止旧调查执行”，成功后展示旧调查已结束、新 Incident ID、有效 scope 和开始执行的状态。
- 失败时区分取消失败、新建失败和新调查已创建但模型启动失败，避免只显示模糊的成功或失败。
- 普通 `/incident new` 在执行中被拒绝时，提示用户可先取消，或使用未来的 `--force` 命令。

## 待决定项

- 普通 `/incident new <问题>` 是否也应创建后立即执行？倾向统一为“创建并执行”，但这会改变当前命令语义，实施前需要明确确认。
- 如果仍需要只创建不执行，是否提供独立选项，以及其命名。
- 继续调查的归属反馈放在状态区还是对话中的应用提示；需兼顾可发现性与重复输入时的噪声。
- 模型启动或凭证预检在替换流程中的具体位置，以及启动失败后的重试交互。
- 当前会话历史继续可见时，如何提示模型区分旧调查的历史信息与新调查可引用的证据；旧证据 ID 不能作为新调查的证据引用。

## 后续实现验收要点

- 空闲和执行中均可按约定创建并启动新调查；普通命令与 `--force` 的差别清楚。
- 活跃调用、排队调用、迟到结果、取消失败和连接变化均不造成跨 Incident 写入或权限泄漏。
- 新调查使用 next selection；旧范围和已消耗预算不被改写，预算仅因创建独立的新 Incident 而重新计数。
- 无效问题或不可用范围不提前结束旧 Incident；部分失败准确反馈实际状态。
- 重复提交切换命令不会意外创建多个调查或重复启动模型。
- 正常和窄终端下，调查归属、停止过程、成功及失败提示均可读。
